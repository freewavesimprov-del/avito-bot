# Каталог, сценарии и playground

Страница `/admin/catalog` теперь объединяет импорт каталога, редактор общения и
playground. Альтернативный адрес — `/admin/studio`. Оба адреса и все API требуют
существующие `ADMIN_USER` / `ADMIN_PASSWORD`. В публичном окружении используйте
HTTPS. Страница доступна и при `APP_ENV=prod`; включать публичный dev-чат не нужно.

## Каталог

1. Выберите выгрузку Авито или прежний Excel из 1С и нажмите «Проверить файл».
2. Проверьте количество объявлений/вариантов, добавления, удаления и изменения.
   Пропущенные размеры — предупреждение; неправильные цены или ID — ошибка.
3. Выберите объявление в playground и проверьте диалог с черновиком каталога.
4. Нажмите «Применить каталог». Только теперь он заменит текущий файл.

Авито импортируется со всех товарных листов. Справочники и служебные строки
пропускаются. Поддерживаются выгрузки, в которых размер листа ошибочно указан как
`A1`. Сохраняются ID объявления, категория, цена, цвет, размеры в сантиметрах,
характеристики, описание и география. Телефоны, почта и контактные лица не
импортируются. Статус объявления «В наличии» не считается подтверждением склада.

Объявления разных городов сохраняются отдельно. Для выдачи одинаковые варианты
группируются по подсказке модели/серии, характеристикам и цене; заголовок и
описание могут отличаться. Эта группировка предварительная, не справочник
производителя. Выбранное объявление сохраняет приоритет перед географическими
дубликатами. Цвета нельзя переносить на товар с другой конструкцией/размерами.

Каталог Авито является самостоятельным источником: старый manual-слой не
добавляется к нему, чтобы не смешивать объявления со старыми ценами. Файл ручных
дополнений не удаляется. Для импорта 1С объединение с manual сохраняется.

Предыдущие каталоги доступны в разделе отката; хранятся последние 30 версий.
Применение проверяет, что текущий каталог не изменился после предпросмотра.
При конфликте повторите загрузку. При удалении объявлений из нового файла они
удаляются и из опубликованного каталога.

## Настройки общения

- Основная инструкция: роль и общие правила. Каталог вставляется в место
  `{{ SKUS_TABLE }}`; отдельные цены сюда вписывать не нужно.
- Условия магазина: утверждённые тарифы, сроки, адреса и FAQ.
- Шаблоны: именованные образцы ответов с возможностью отключения и удаления.
- Сценарии: условие применения и последовательность шагов. Условия ветвления
  задаются словами в шагах. Это инструкции для модели, а не гарантированная
  программная машина состояний.

При первом открытии исходная версия загружается из существующих system_prompt.md
и faq_extras.md. В карточках уже есть сценарии наличия, доставки, выбора варианта
и передачи из действующей инструкции, а также существующая фраза передачи из кода.
Основная инструкция открыта для просмотра. Кнопка «Взять действующие настройки
за основу» заменяет черновик опубликованной версией, а до первой публикации —
настройками из файлов проекта. Сама кнопка ничего не публикует.

«Сохранить черновик» не меняет опубликованные настройки. Playground проверяет
сохранённый черновик; несохранённые правки сохраняются перед тестовым сообщением.
«Опубликовать для бота» применяет настройки к следующим генерациям без рестарта.
Последние 20 предыдущих опубликованных версий можно восстановить в черновик и
опубликовать заново. Обновление защищено от перезаписи правок из другой вкладки.

Существующие программные фильтры и жёсткие триггеры продолжают действовать.
Редактирование текста не разрешает внешние ссылки, контакты, конкретные скидки
или запрещённые точные даты. Противоречия между базовой инструкцией, FAQ и
сценарием нужно разрешить до публикации. Новые неподтверждённые тарифы из
предложения регламента автоматически не включаются.

## Playground

- Выберите черновик или опубликованные настройки.
- При наличии загрузки режим черновика использует новый каталог до применения.
- Найдите и выберите исходное объявление клиента, затем напишите сообщение.
- Ответы генерирует только YandexGPT. Подставных ответов в playground нет.
- Форма подключения содержит API-ключ, ID каталога и модель. Изначально
  подхватываются существующие `YC_API_KEY`, `YC_FOLDER_ID`, `YC_MODEL`.
  Пустое поле ключа сохраняет уже настроенный ключ. Сам ключ не возвращается
  в браузер. Проверка соединения выполняет короткий запрос с введёнными
  параметрами без сохранения; сохранение — отдельная кнопка.
- Сохранённое подключение используется общим клиентом YandexGPT для бота
  и playground без рестарта. Запросы расходуют квоту. До настройки подключения
  тестовый чат недоступен. В playground общий `MOCK_LLM` не подменяет модель;
  ошибки соединения отображаются явно.
- Передача менеджеру имитируется. После неё начните новый разговор.

Playground не вызывает Bitrix, Avito или Telegram и не пишет в SQLite клиентских
диалогов. История хранится в памяти страницы и исчезает при обновлении. Расписание
ответов/передачи не ограничивает тестовые сообщения; реальные клиенты по-прежнему
обрабатываются с расписанием. Данные черновика и режим модели изолированы на
уровне запроса и не меняют настройки параллельных продовых запросов.

## Хранение и обновление

Рабочий каталог остаётся по `CATALOG_PATH`. Черновики, настройки и версии лежат в
соседней папке `.studio/`. Она должна быть доступна на запись пользователю сервиса
и сохраняться при обновлении приложения. Не копируйте эти данные в публичный Git.
Запись JSON атомарная; изменения состояния сериализованы файловой блокировкой.
API-ключ, введённый через форму, хранится только в
`.studio/credentials/yandex.json` с правами `0600`, папка credentials имеет права
`0700`. Весь каталог `.studio/` исключён из Git. Поля ключа нет в ответах API,
истории регламентов и каталоге товаров. Существующие переменные окружения не
перезаписываются. Доступ к серверу и его резервным копиям должен быть ограничен.

Старый API `/admin/catalog/upload` оставлен для загрузок 1С из существующего
CLI. Выгрузку Авито он не применяет напрямую: используйте новую страницу или
`POST /admin/studio/catalog/preview`, затем `POST /admin/studio/catalog/apply`.

Изменения приложения требуют обычного обновления кода и рестарта сервиса.
Загруженные каталоги и опубликованные настройки после этого не требуют рестарта.
Данная разработка проверена локально; автоматически на VPS она не разворачивается.
