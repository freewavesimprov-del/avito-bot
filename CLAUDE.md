# CLAUDE.md — контекст проекта для Claude Code

Это рабочий проект — чат-бот для магазина мебели «Недорогая мебель» на Авито, работающий через Битрикс24.

## Что за проект

**Цель:** автоматизировать первый контакт с клиентом в Авито-мессенджере. Бот отвечает на типовые вопросы (FAQ), квалифицирует горячих клиентов и передаёт их менеджеру. Менеджер работает в Битрикс24.

**Контекст бизнеса:**
- Компания «Недорогая мебель» — кабинет на Авито `i455406`, 13 лет на рынке, свой склад в МО, офлайн-точки в Шатуре, Егорьевске, Орехово-Зуево.
- Пилотная волна на Авито — 18 SKU (диваны, комоды, шкафы, кровати, прихожая). Актуальные цены и остатки — в файле `app/data/pilot_skus.json` (выгрузка из 1С на 22.04.2026).
- Менеджеры работают с клиентами через **Битрикс24 Открытые линии**. Авито ↔ Битрикс связан штатным коннектором Bitrix24.

## Архитектура

```
Клиент в Авито
    ↓
Avito Messenger (штатный коннектор B24)
    ↓
Открытая линия в Битрикс24 (бот назначен первым оператором очереди)
    ↓ событие ONIMBOTMESSAGEADD
Bot Platform Bitrix24 → webhook на ваш сервер
    ↓
[Наш бэкенд FastAPI]
 ├─ Pre-filter: блокировка спама/оффтопика/токсичности
 ├─ Hard-triggers: жалобы, «позовите человека» → сразу эскалация
 ├─ LLM (YandexGPT Lite) с system prompt + inject актуальных SKU
 ├─ Post-filter: проверка на телефоны/ссылки/обещания скидок
 ├─ Логирование (SQLite)
 └─ Эскалация → imbot.chat.leave + комментарий к лиду
    ↓
imbot.message.add → Открытая линия → Авито → Клиент
```

## Технический стек

- **Python 3.11+** (минимум 3.10)
- **FastAPI** — webhook-сервер, принимает события от Битрикса
- **uvicorn** — ASGI-сервер
- **httpx** (async) — вызовы к YandexGPT API и Bitrix REST
- **pydantic v2** — модели данных для event payload и конфига
- **SQLite** + SQLAlchemy async — логи диалогов, статистика
- **python-dotenv** — конфиг через `.env`
- **pytest** + pytest-asyncio — тесты
- **ruff** — линтер/форматер

## Ключевые принципы

1. **LLM-first, без regex-FAQ.** Вся бизнес-логика ответов держится на system prompt и post-filter, не на жёстких шаблонах.
2. **Строгие границы через post-filter.** Бот НЕ должен отправлять клиенту: телефоны, email, ссылки на WhatsApp/Telegram/внешние сайты, обещать конкретную скидку, называть точную дату доставки, обсуждать оффтопик.
3. **Эскалация — это не failure, это feature.** Лучше передать менеджеру, чем ошибиться. Триггеры: низкая уверенность LLM, хард-триггеры (жалоба/брак), клиент запросил человека, дошло до оформления заказа.
4. **Молчать когда менеджер в чате.** Если `ONIMBOTDELETE` или менеджер ответил — бот выходит из игры до нового диалога.
5. **Логировать всё.** Каждое входящее сообщение, ответ LLM, срабатывание post-filter, эскалация — в SQLite. Через месяц — отчёт для расширения промпта.

## Что НЕ делать в MVP

- Не интегрироваться с 1С напрямую (данные об остатках/ценах — из локального JSON-файла, обновляется вручную раз в день или по крону).
- Не писать визуальный интерфейс администратора (через месяц можно).
- Не массовые рассылки (Авито запрещает).
- Не кастомные NLU/intent-классификаторы — всё через LLM + простые regex в post-filter.

## Критерии готовности MVP

- [ ] Бот регистрируется в Битриксе (скрипт `scripts/register_bot.py`)
- [ ] Бот отвечает на входящее сообщение в тестовой Открытой линии (через YandexGPT)
- [ ] Post-filter блокирует ответы с телефонами/ссылками/обещаниями скидок (тесты зелёные)
- [ ] Хард-триггеры передают диалог менеджеру (эмуляция в тесте)
- [ ] Бот замолкает если менеджер вступил в диалог
- [ ] Логи пишутся в SQLite с timestamp и типом события
- [ ] Конфиг в `.env`, секреты нигде не хардкодятся
- [ ] `README.md` описывает: как запустить локально, как деплоить на VPS, как регистрировать бота
