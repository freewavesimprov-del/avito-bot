# SPEC — чат-бот Авито × Битрикс24

Детальное ТЗ для разработки и калибровки бота.

## 0. Модель интеграции с Bitrix24

Бот реализуется как **локальное приложение Bitrix24** (а не входящий вебхук). B24 при событиях шлёт POST на наш URL, в теле — `auth.access_token`, `auth.domain`, `auth.application_token`. HMAC-подписи заголовком B24 **не шлёт**. Вся аутентификация вебхука — сверка `auth.application_token` с сохранённым при установке значением (`B24_APPLICATION_TOKEN` в `.env`). При событии `ONAPPINSTALL` приложение получает и сохраняет `application_token`.

### События, которые обрабатываем

| Событие | Действие |
|---|---|
| `ONAPPINSTALL` | Сохранить `application_token` (первая установка) |
| `ONIMBOTJOINCHAT` | Зарегистрировать `dialog_id` в `dialogs`, ничего не отвечать |
| `ONIMBOTMESSAGEADD` | Главный обработчик (см. §1) |
| `ONIMBOTDELETE` | Пометить `dialog_id.operator_led = true`, больше не отвечать в этом диалоге |
| `ONIMBOTMESSAGEUPDATE` / `ONIMBOTMESSAGEDELETE` | Логируем, не реагируем |
| Прочее | 200 OK + лог, без действий |

## 1. Поток данных

### 1.1 Входящее событие от Битрикса

Битрикс шлёт POST на наш webhook с событием `ONIMBOTMESSAGEADD`. Ключевые поля:

```
event: "ONIMBOTMESSAGEADD"
data:
  PARAMS:
    MESSAGE_ID: 12345
    MESSAGE: "Здравствуйте, Комод Ангара в наличии?"
    DIALOG_ID: "chat123"
    FROM_USER_ID: 987         # ID клиента (external) или оператора
    BOT_ID: 100
  USER:
    ID: 987
    NAME: "Иван"
    IS_EXTRANET: true         # true = клиент, false = оператор
auth:
  access_token: "..."
  domain: "your-company.bitrix24.ru"
  application_token: "..."    # сверяем с B24_APPLICATION_TOKEN (иначе 401)
```

### 1.2 Решение: отвечать или нет

```
1. IF USER.IS_EXTRANET == false → игнорируем (это оператор пишет).
2. IF dialogs[DIALOG_ID].operator_led == true → игнорируем (оператор уже ведёт).
3. IF в events за последние 60 сек есть direction=out с bot=false → игнорируем.
4. IF хард-триггер срабатывает → эскалация без LLM.
5. ELSE → debounce (см. §9) → прогон через LLM → post-filter → отправка.
```

Первичный сигнал «менеджер в чате» — событие `ONIMBOTDELETE` (бота исключили из чата). По нему выставляем `dialogs.operator_led = true` и больше не отвечаем в этом `DIALOG_ID` до новой сессии. Вторичный сигнал (пункт 3) — подстраховка.

### 1.3 Отправка ответа

```
POST /rest/imbot.message.add
  BOT_ID: 100
  DIALOG_ID: "chat123"
  MESSAGE: "Да, по данным на 22.04 в наличии 5 штук..."
  ATTACH: null
```

### 1.4 Эскалация менеджеру

```
1. Отправить клиенту фиксированное сообщение:
   "Секунду, передаю вопрос менеджеру — ответит в этом же чате".
2. Вызвать imbot.chat.leave — бот выходит, Битрикс передаёт диалог следующему оператору в очереди.
3. Пометить dialogs[DIALOG_ID].operator_led = true.
4. Опционально: добавить комментарий к лиду через crm.timeline.comment.add
   с причиной эскалации и (если применимо) с текстом, который LLM хотел отправить, но post-filter заблокировал.
```

## 2. Хард-триггеры эскалации (bypass LLM)

Если в сообщении клиента есть любой из паттернов — НЕ вызывать LLM, сразу эскалация.

| Категория | Примеры ключевых слов / regex |
|---|---|
| Жалобы | `жалоб`, `брак`, `сломал`, `не работает`, `дефект`, `плохое качество`, `рекламаци` |
| Возврат | `верните деньги`, `возврат`, `вернуть товар`, `отказ от покупки` |
| Запрос менеджера | `позовите (менеджера|оператора|человека)`, `дайте (телефон|контакт)`, `давайте созвонимся` |
| Сложные переговоры | `скидк`, `дешевле`, `уступите`, `торг` — по желанию, спорно, можно отдать в LLM с правилом не обещать |
| Упоминание номера заказа | regex `\b\d{6,}\b` (шестизначные и более числа) |
| Юридические вопросы | `договор`, `судебный`, `законн` |

Для жалоб — отдельный комментарий в лид: «⚠ Жалоба/рекламация, требует приоритета».

## 3. System prompt

Текст в `app/prompts/system_prompt.md`. Структура:

```markdown
# Роль
Ты — ассистент магазина мебели «Недорогая мебель» на Авито. Работаешь 
в Messenger, отвечаешь покупателям на русском языке. Твоя задача — 
закрыть простые вопросы и аккуратно передать сложные менеджеру.

# Контекст компании
- 13 лет на рынке
- Склад в МО, офлайн-магазины в Шатуре, Егорьевске, Орехово-Зуево
- Работаем с физлицами, принимаем оплату при получении и Авито Доставку
- Доставка по МО 2 000 ₽, срок 1-3 дня
- Самовывоз со склада — бесплатно, с офлайн-точек — бесплатно
- Гарантия 12 месяцев
- Подъём на этаж — отдельная услуга, считает менеджер

# Товары в наличии (на {{ UPDATED_DATE }})
{{ SKUS_TABLE }}   ← компактная markdown-таблица "артикул | название | цена | остаток",
                     собирается prompt_builder-ом из data/pilot_skus.json (~300 токенов)

# Стиль ответов
- Коротко: до 300 символов, без списков, без эмодзи
- Вежливо и по делу
- Говори «по данным на 22.04» когда утверждаешь про остаток
- Если чего-то не знаешь — «Уточню у менеджера и напишу»

# ЖЁСТКИЕ ЗАПРЕТЫ (НИКОГДА не делать)
- НЕ давать свой или чужой телефон, email, ссылки на WhatsApp/Telegram/сторонние сайты
- НЕ обещать конкретную скидку в рублях или %. Только «скидку согласует менеджер»
- НЕ обещать точную дату доставки. Только «срок 1-3 дня, точную дату согласует менеджер»
- НЕ давать советы вне мебели (погода, политика, личное)
- НЕ обсуждать конкурентов

# Когда передавать менеджеру
Напиши "ESCALATE: <причина>" в конце ответа, если:
- Клиент хочет оформить заказ (адрес, дата, оплата) — передай менеджеру после 
  подтверждения наличия
- Клиент спрашивает цвет/материал, которого нет в списке
- Клиент просит видео товара, замер, примерку на месте
- Ты не уверен в ответе (меньше 70% уверенности)

# Примеры диалогов
[Клиент] Комод Ангара Графит в наличии?
[Бот] Да, по данным на 22.04 в наличии 5 шт. Цена 14 000 ₽. Нужна доставка 
или самовывоз?

[Клиент] А какая скидка?
[Бот] Скидки согласует менеджер, передам запрос. ESCALATE: запрос скидки

[Клиент] Дайте телефон
[Бот] В Авито-чате я могу помочь с типовыми вопросами. По сложным вопросам 
передам менеджеру, он напишет в этом же чате. ESCALATE: запрос контакта
```

## 4. Post-filter (проверка ответа LLM) и парсинг ESCALATE

### 4.1 Парсинг маркера ESCALATE

Строго: `re.search(r'(?m)^\s*ESCALATE:\s*(.+?)\s*$', text)`. Если маркер найден:
- причина эскалации = captured group
- строка с маркером **вырезается** из текста, клиенту идёт только оставшееся (если post-filter пропустил)

В post-filter добавлен ассерт: если в финальном тексте для клиента осталась подстрока `ESCALATE`, ответ блокируется как `leaked_marker`.

### 4.2 Regex-фильтры

Перед отправкой клиенту прогоняем ответ LLM через набор regex. Если хоть один паттерн нашёлся — ответ НЕ отправляется, срабатывает эскалация (см. §1.4).

```python
BLOCKED = [
    (r'\+?7?\s?\(?\d{3}\)?\s?\d{3}[-\s]?\d{2}[-\s]?\d{2}', 'phone'),
    (r'[a-z0-9._%+-]+@[a-z0-9.-]+\.\w+', 'email'),
    (r'(whatsapp|ватсап|telegram|телеграм|tg\.me|wa\.me|t\.me)', 'messenger_link'),
    (r'(\d+\s?(%|процент)|скидк[аяуе]\s+\d+|скину\s+\d+|уступлю\s+\d+)', 'specific_discount'),
    (r'(завтра|послезавтра|через \d+ дн)', 'specific_date'),
    (r'(https?://|www\.)', 'external_link'),
    (r'ESCALATE', 'leaked_marker'),
]
```

При срабатывании:
1. Клиенту уходит фиксированный текст из §1.4 (не «заглушка от LLM»).
2. В лид пишется: «Бот хотел ответить: `<текст>`, заблокировано по причине: `<причина>`. Передано менеджеру».
3. `dialogs[DIALOG_ID].operator_led = true`.

## 5. Интеграция с YandexGPT

- **Модель:** `yandexgpt-lite` (или `yandexgpt` для Pro). На 30 диалогов/день обычно хватает Lite.
- **Auth:** Yandex Cloud API key + folder_id.
- **Endpoint:** `https://llm.api.cloud.yandex.net/foundationModels/v1/completion`
- **Параметры:**
  - `temperature`: 0.3 (низкая — чтобы меньше импровизировал)
  - `maxTokens`: 200 (ответ до 300 символов)
  - `stream`: false
- **System prompt** подаётся как первое сообщение с `role: system`.
- **History:** последние 10 сообщений диалога из нашей таблицы `events` (по `dialog_id`). Не используем `im.dialog.messages.get` — не требуется расширенных прав.
- **Таймаут:** `YC_TIMEOUT_SEC=8`, 2 ретрая с экспоненциальной паузой. При полном фейле — эскалация с клиентским текстом «Уточню у менеджера, ответит в этом же чате».
- **Debounce:** если от одного `dialog_id` за последние `DEBOUNCE_SEC=10` сек пришло ≥2 сообщения, ждём `DEBOUNCE_SEC`, затем вызываем LLM один раз со склеенным текстом.

## 7. База данных (SQLite)

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    dialog_id TEXT NOT NULL,
    user_id TEXT,
    direction TEXT CHECK(direction IN ('in', 'out', 'escalate', 'blocked', 'system')),
    message TEXT NOT NULL,
    meta JSON
);

CREATE INDEX idx_events_dialog ON events(dialog_id, ts);
CREATE INDEX idx_events_direction ON events(direction, ts);

-- Флаг «оператор ведёт диалог» — бот замолкает до нового DIALOG_ID
CREATE TABLE dialogs (
    dialog_id TEXT PRIMARY KEY,
    operator_led BOOLEAN NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Отчёт раз в неделю: SQL-выборка топ вопросов, что попали в эскалацию / блок → расширение system prompt.

## 9. Деплой на VPS

**Основной способ — systemd + venv** (Docker опционально, в MVP не делаем):

- Python 3.11 venv + systemd unit `avito-bot.service`
- Nginx reverse proxy с Let's Encrypt (обязательно HTTPS для вебхука)
- Логирование stdout/stderr в journalctl
- Простой healthcheck endpoint `GET /health`
